## 中文

### 新增

- **云存档文件级差量（manifest 快照）**：整实例归档上传时只传云端缺失的文件，恢复时只下载缺失或哈希不符的文件。传输并发上限 3，遇到限流按服务端建议的退避时间重试；服务端拒绝清单、超出文件数/大小限制或配额不足时，在同一次上传内自动回退为整包 zip，绝不截断内容。实例设置 `-Dxenon.cloud.delta=false` 可停止产生新的差量快照。
- **房主审批列表改为服务端权威快照**：通过 `GET /multiplayer/sessions/{id}/join-requests` 分页拉取；实时事件只作为刷新信号，并保留最近 10 秒由事件新增的条目。断线重连、心跳周期和手动刷新都会重新拉取，漏收事件不再永久丢申请。
- **服务端限额 `capabilities.limits`**：建房人数、大厅分页、邀请与在线连接上限改为跟随服务端声明；邀请超限会提示等待待处理邀请过期。
- **按用户名搜索并邀请非好友**：邀请对话框新增 `GET /users/search` 搜索，非好友会标注“尚非好友”，是否可邀请仍由服务端隐私/好友策略决定。

### 修复

- **建房不再被遗留会话卡死**：返回 `SESSION_ALREADY_ACTIVE` 时先结束旧会话并自动重试一次；仍失败时显示旧会话 id 并提供“重试”按钮。
- **大厅按钮与房间状态一致**：直接读取服务端的 `joinable` / `can_request_join`，不可加入时显示 `blocked_reason` 的本地化原因（已在其他房间、隐私限制、房间已满、仅好友、仅接受申请等），不再由客户端猜测。
- **存档格式错误可读化**：`SAVE_SNAPSHOT_FORMAT_MISMATCH`、`SAVE_BLOB_MISSING`、`SAVE_MANIFEST_INVALID` 等不再显示裸 HTTP 码；单存档页遇到差量快照会标注为“请在实例归档页或网页端恢复”，并禁用无效的下载按钮。
- **恢复的目标文件名做路径净化**：单存档恢复会拒绝包含路径分隔符、盘符或 `..` 的文件名，并校验最终路径仍在存档目录内。

### 稳定性与安全

- 云端上传 URL 只有在与 API 同源时才携带 Bearer token；重定向判断改为比较 scheme、host 与端口，跨源签名 URL 不再收到用户凭证。
- 整实例恢复的本地备份现在包含 `mods/`；manifest 恢复额外校验条目数、总大小、重复路径与每个文件的 SHA-256，任一校验失败都不会改动实例数据。
- 上传前用“缺失字节 / 逻辑字节”的较大值做配额预检，避免差量快照在提交阶段因配额失败。

### 说明

- 实例目录结构、`.xenon` 包格式与存档格式均未改动，回退版本仍可读取整包 zip 快照。
- 差量快照需要服务端在 `quota.formats` 中声明受支持格式；未声明时客户端继续使用整包 zip。
- 已存在的整包快照与本地 `cloud-sync.json` 基线无需迁移。

## English

### Added

- **File-level delta snapshots for cloud archives**: an instance-archive upload now transfers only the blobs the cloud is missing, and a restore downloads only files that are missing or hash-mismatched. Transfers use at most three workers and honour the server-advertised retry delay; when the server rejects the manifest, a file-count/size limit is exceeded, or the quota check fails, the same upload falls back to the whole-archive zip without truncating anything. Set `-Dxenon.cloud.delta=false` on an instance to stop producing new delta snapshots.
- **Host join requests now come from the server snapshot**: the host reads `GET /multiplayer/sessions/{id}/join-requests` with pagination, realtime events only trigger a throttled refresh, and entries added by an event in the last 10 seconds are kept. Reconnects, the heartbeat and the manual refresh all re-read it, so a dropped event no longer hides a request forever.
- **Server limits from `capabilities.limits`**: hosted player count, lobby page size, invite limits and presence connections follow the advertised values; hitting the invite cap explains how long to wait.
- **Search non-friend users by name and invite them**: the invite dialog uses `GET /users/search` and marks results as "Not a friend yet"; whether an invite is allowed is still decided by the server's privacy/friend policy.

### Fixed

- **Creating a room is no longer blocked by a stale session**: on `SESSION_ALREADY_ACTIVE`, Xenon closes the leftover session and retries once, then shows the old session id with a Retry action if it still fails.
- **Lobby buttons match the real room state**: they follow the server's `joinable` / `can_request_join` and show the localized `blocked_reason` (already in another room, privacy restriction, full, friends-only, request-only, and so on) instead of guessing from `require_approval`.
- **Readable save-format errors**: `SAVE_SNAPSHOT_FORMAT_MISMATCH`, `SAVE_BLOB_MISSING` and `SAVE_MANIFEST_INVALID` no longer surface as raw HTTP codes; a delta snapshot in the single-save tab is marked as restore-from-archive and its download button is disabled.
- **Restore target names are sanitized**: single-save restore rejects names containing separators, drive letters or `..`, and verifies the final path stays inside the saves directory.

### Stability and security

- Bearer tokens are only attached to upload URLs on the API origin; redirect handling now compares scheme, host and port, so cross-origin signed URLs never receive user credentials.
- The pre-restore backup now includes `mods/`; manifest restores additionally verify the entry count, total size, duplicate paths and every SHA-256, and never touch instance data when a check fails.
- The upload pre-check charges `max(missing bytes, logical bytes)` against the quota, so a delta snapshot cannot fail only at commit time.

### Notes

- Instance layout, the `.xenon` package format and save formats are unchanged; older builds can still read whole-archive zip snapshots.
- Delta snapshots require the server to advertise a supported format in `quota.formats`; otherwise the client keeps using the whole-archive zip.
- Existing zip snapshots and local `cloud-sync.json` baselines need no migration.
