## 中文

Xenon v1.12.0 修复了实例归属与重命名相关的问题，让「游戏文件夹 + 独立数据目录」真正按预期工作。

### 主要更新

- 新导入或安装的 Mindustry 实例现在写入当前游戏文件夹自己的 `versions/` 目录；新增自定义游戏文件夹后，实例不会再落到共享的 `%APPDATA%\Xenon` 仓库。
- 从 Steam 或本地文件夹识别到的外部安装会注册到当前游戏文件夹；只有数据目录确实位于安装目录内（Steam / 便携版）时才复用，否则改为实例隔离目录，不再默认绑定 `%APPDATA%\Mindustry`。
- 重命名实例会正确移动实例目录、重写 `version.json` 并同步 jar 文件名，目录名与实例 id 不再脱节；被旧逻辑改坏的实例会按目录名自动修复，无需重新安装。
- 修复 Minecraft 版本扫描把 Mindustry 的 `version.json` 改名为 `<id>.json` 的问题，避免实例元数据（尤其是数据目录设置）被覆盖。

### 校验

- 通过 Xenon / XenonCore 编译与 Checkstyle 检查，以及相关 JUnit 用例（重命名、扫描隔离、外部安装归属）和 147 项 XenonCore 回归用例。

## English

Xenon v1.12.0 fixes instance ownership and renaming so that the "game folder + isolated data directory" model works as intended.

### Highlights

- Newly imported or installed Mindustry instances are written into the current game folder's own `versions/` directory; after adding a custom game folder, instances no longer fall back to the shared `%APPDATA%\Xenon` repository.
- External installations detected in Steam or a local folder are registered in the current game folder. Their data directory is reused only when it actually lives inside the installation folder (Steam / portable builds); otherwise the instance is isolated instead of silently binding to `%APPDATA%\Mindustry`.
- Renaming an instance now moves its directory, rewrites `version.json` and renames the jar file, so the id can no longer drift away from the folder name. Instances broken by the old behaviour are repaired automatically, without reinstalling.
- Fixed HMCL's Minecraft version scan renaming Mindustry `version.json` files to `<id>.json`, which used to overwrite instance metadata (especially the data directory policy).

### Verification

- Passed Xenon / XenonCore compilation, Checkstyle, the related JUnit tests (rename, scan isolation, external-install ownership) and 147 XenonCore regression tests.
