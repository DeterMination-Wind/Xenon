## 中文

### 本次修复

- **Windows 单文件 exe 自动更新恢复**：旧版本点击“更新”后只会下载 jar，随后因为内置 runtime 没有 `java.exe` 而静默失败。现在 exe 构建会下载并替换外层 exe，等待旧进程退出后解包新 bundle 并启动。
- **先看更新说明，再开始下载**：点击新版本提示横幅会先展示更新日志，只有点击“更新”按钮后才开始下载，取消不会产生任何下载或文件改动。
- **更新失败不再静默**：下载完成后的进程交接异常会弹出错误提示，并给出手动下载入口。
- **bundle 替换更稳**：新 bootstrap 会等待旧启动器退出后再替换 `Xenon.bundle`，避免目录被占用导致更新失败。

### 说明

- 2.0.1 及更早的 Windows exe 用户需要手动下载一次 2.0.2；之后可正常自动更新。
- jar 用户（macOS / Linux / 手动 `java -jar`）不受影响。
- 实例、存档、联机数据格式均未改动。

## English

### Fixed

- **Auto-update works again for the Windows single-file exe**: older builds downloaded the jar and then failed silently because the packaged runtime has no `java.exe`. The exe build now downloads and replaces the outer executable, waits for the old process to exit, unpacks the new bundle and starts it.
- **Changelog first, download second**: clicking the new-version banner shows the release notes first; the download only starts after the Update button is pressed, and cancelling leaves no downloaded file or state change.
- **Update failures are visible**: handover errors after a successful download now show an error dialog with a manual download link instead of doing nothing.
- **More reliable bundle replacement**: the new bootstrap waits for the previous launcher to exit before swapping `Xenon.bundle`, so a locked directory no longer breaks the update.

### Notes

- Windows exe users on 2.0.1 and older need to download 2.0.2 manually once; automatic updates work from 2.0.2 onward.
- Jar users (macOS / Linux / manual `java -jar`) are unaffected.
- Instance, save and multiplayer data formats are unchanged.
