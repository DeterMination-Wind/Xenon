## 中文

Xenon v1.13.1 修复了日志入口打不开日志、以及默认游戏文件夹路径仍是 `.minecraft` 的问题。

### 修复与优化

- 「日志」页的「最后的日志」和游戏异常退出弹窗里的「打开日志文件」不再提示「未找到 last_log.txt」。现在会按 游戏自己的 `last_log.txt` → 启动器记录的本次启动输出 → 最新崩溃报告 的顺序依次取用；实例还没有任何日志时会直接打开日志文件夹并说明原因。
- 启动器会为每次启动单独保存一份进程输出到实例目录下的 `logs/`（自动只保留最近 10 份）。即使游戏在写出自己的日志前就崩溃，也能从不依赖游戏数据目录的这份日志里看到完整报错。
- 「日志」页会跟随实例真正的启动数据目录：选择存档归档启动时，日志与崩溃报告也指向实际使用的那份数据目录。
- 「添加游戏文件夹」与新建配置的默认路径改为官方 Mindustry 数据目录（Windows 下为 `%APPDATA%\Mindustry`），并清理了设置中剩余的 `.minecraft` 示例地址。

### 校验

- 通过 Xenon / XenonCore 编译、Checkstyle、翻译检查与全部单元测试；新增日志解析与启动日志抓取（真实进程启动失败场景）回归测试。

## English

Xenon v1.13.1 fixes the log entry points that could not open a log, and the remaining `.minecraft` default folder path.

### Fixes and improvements

- "Last log" on the Logs tab and "Open log file" in the abnormal-exit dialog no longer report a missing `last_log.txt`. They now use the game's own log first, then the launcher-captured output of the latest launch, then the newest crash report; an instance with no logs at all opens its log folder instead of ending in a dead end.
- Every launch keeps its process output under `logs/` inside the instance folder (the latest 10 files are kept). Even when the game dies before writing its own log, the full error output is still available outside the game data directory.
- The Logs tab follows the effective launch data directory, so save-archive runtimes show their own logs and crash reports.
- The default path for "Add game folder" and for new profiles is now the official Mindustry data directory (`%APPDATA%\Mindustry` on Windows); the remaining `.minecraft` example paths were removed.

### Verification

- Passed Xenon / XenonCore compilation, Checkstyle, translation checks and all unit tests; added regression tests for log resolution and for capturing the output of a real failing launch process.
